# BUG-001: "Spectate" on the death card leaves a ~4 s dead gap before spectating starts

- **Severity:** S3 (major UX, not blocking). Production scale: P2.
- **Build:** working tree 2026-11-18 (no git commits yet); `npx tsc --noEmit -p .` clean, `npx vitest run` 693/693.
- **Suspected owner:** game-developer (`src/game/ClientGame.ts` `isSpectating()`), with ui-ux-designer (`src/ui/Ui.ts` death card) for the intent.

## Steps to reproduce
1. Start a stack with a short tide so the idle human dies (as in `tests/e2e/match-loop.spec.ts`), join, and don't move.
2. When the "Washed out!" death card appears, click **Spectate** immediately.

## Expected
Clicking Spectate starts spectating right away (GDD §4.4 / UI.md flow: "Death card → Spectate → spectate bar"), or the
button is disabled/absent until spectating is possible.

## Actual
The card closes, but no spectate bar appears and the camera stays on the player's own body for about 4 s. Only then does
"Spectating <name>" appear. Timeline from a probe (screen state polled every ~150 ms, 2-3 players still alive):

```
15.3 s  death card visible
        clicked Spectate
15.9 s  death card hidden, spectate bar hidden   <- nothing on screen
20.1 s  spectate bar "Spectating Cap'n Driftwood"
```

When the match ends within that window (the last bots die), the player never sees spectate at all.

## Cause (from code reading)
`Ui` closes the card on click (`DeathCard(() => this.closeDeath())`), but `ClientGame.isSpectating()` only returns
true once `this.time - this.localDeathAt >= balance.match.deathScreenSeconds`. Nothing tells ClientGame that the player
asked to spectate early. Possible fixes: a `UiCallbacks.onSpectate()` intent that clears the gate, or keeping the card
up (button disabled) until `hud.spectate` is non-null.

## Evidence
- `tests/e2e/match-loop.spec.ts` (full loop) logs `spectate bar appeared N ms after clicking Spectate (BUG-001)` and
  allows 8 s for the bar.
- Screenshots: `test-results/shots/loop-death.png`, `test-results/shots/loop-spectate.png`.
