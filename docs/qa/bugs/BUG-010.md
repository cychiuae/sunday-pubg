# BUG-010: A client stall over 200 ms while holding LMB/RMB fires a semi-auto gun again and drops ADS on the server

- **Severity:** major (unintended shots with the dmr/sniper/pistol/shotgun, and a scoped player is silently un-scoped
  on the server while the client still shows the scope; only after an input gap > 200 ms, e.g. a frame hitch, GC
  pause or alt-tab).
- **Build:** working tree 2026-11-18.
- **Suspected owner:** game-developer (`World.dequeue` / `handleFire` in `src/shared/sim/World.ts`); tech-lead for the
  `MAX_INPUT_REPEAT_TICKS` rule (`src/shared/constants.ts`).

## Steps to reproduce
1. `npx vitest run tests/sim/m2a-edge.test.ts -t "stall"` (two `it.fails` tests document it).
2. Or in the browser (headless runs at ~10 fps, so stalls are common): equip a semi-auto shotgun, click LMB once
   (down, 120 ms, up). `tests/e2e/gameplay.spec.ts` logged "mag 5 -> 3, shot events 0 -> 2" for that single click.

## Expected
- One press of a semi-auto weapon fires one shot (combat.md AT6) however the inputs arrive.
- Holding RMB keeps ADS; the server and client prediction agree (stance.md AT16 / 2a-C5 "no rubber-banding").

## Actual
When no input arrives for more than `MAX_INPUT_REPEAT_TICKS` (6 ticks = 200 ms), `dequeue` returns a neutral input
with `fire: false, ads: false`. `handleFire` stores `prevFire = false` and clears `triggerLatched`, and the movement
step resets `adsMs` to 0. When the client's queued inputs arrive (button still held, `fire: true`, `ads: true`):
- `fire && !prevFire` is a new trigger edge, so a semi-auto gun fires again: 2 shots for one press in the sim test
  (dmr, 10-tick stall) and in the E2E (shotgun).
- ADS restarts from 0 on the server (sniper: 400 ms to re-scope, hip spread meanwhile) while the client predicted it
  stayed scoped, so the next snapshot corrects `adsMs` and the first shot after the hitch uses hip spread.
A 6-tick stall (within the budget) behaves correctly (control test passes).

## Suggested fix
Treat the injected neutral input as "no information", not as a release: do not update `prevFire` /
`triggerLatched` from a stall-neutral input, and freeze (do not reset) `adsMs` during the stall; resume from the
next real input. Keep the neutral move/sprint/fire so a stalled tab still stops moving and shooting.

## Evidence
- `tests/sim/m2a-edge.test.ts` "input stalls (> MAX_INPUT_REPEAT_TICKS) ..." (actual: `expected 2 to be 1`, ADS trace
  back to 0).
- `tests/e2e/gameplay.spec.ts` notes, run 2026-11-18 09:3x: `before LMB: HUD mag 5, server shots so far 0` then
  `mag 5 -> 3, shot events 0 -> 2`.
