# BUG-016: Name tags are not hidden behind smoke (PlayerView.smokeHidden stays false)

- **Severity:** major (smoke.md 11 / M2C-UI-21..23: a player behind a smoke cloud keeps a visible name tag and spectate
  outline, so smoke does not hide position; the sim and bots treat the cloud as opaque, the client view does not).
- **Build:** working tree 2026-11-18, M2c closing round (BUG-014 hook fields in).
- **Suspected owner:** game-developer (`src/game/ClientGame.ts`, the `PlayerView.smokeHidden` line in the frame build,
  `playerHiddenBySmoke`).

## Steps to reproduce
1. `npm run e2e:local -- tests/e2e/m2c.spec.ts` (island, `LAYOUT_SEED=4821`, two browsers A and B ~19 m apart).
2. A throws a smoke; A then stands 3 m beyond the cloud edge on the far side from B, so the cloud sits on the A-B line.
3. Read `window.__game.players.find(p => p.name === 'QA Bravo').smokeHidden` on A (and the mirror on B).

## Expected
`smokeHidden: true` on both browsers once the cloud has grown (the camera's lines to the head and the chest both cross the
opaque sphere).

## Actual
Run log (`smoke diag` / `client rule` notes): cloud radius 6.50, centre (83.6, 3.7, 14.6); A eye (74.5, 3.5, 13.6), outside
the cloud (`inSmoke false`); B at (97.5, 16.3) standing; the eye-to-head segment passes 0.24 m from the cloud centre.
- The client's own rule, `hiddenBySmoke(clouds, cam, head, chest, serverTime, BALANCE.items.smoke.cloud)` from
  `src/game/smokeView.ts`, evaluated in the same page on the hook's cloud record
  (`{"id":1,"pos":{"x":83.575,"y":2.525,"z":14.593},"deployedAt":343628.577,"fadeAt":363128.577}`, now 351421.9) -> **true**.
- `__game.players[B].smokeHidden` on A -> **false** for 6 s of polling (and on B for A). Reproduced on 3 runs.
Not checked: whether the renderer draws B's name tag in that frame (A faced away after the walk, so no screenshot shows
it). The finding is on `PlayerView.smokeHidden` as the dev hook exposes it. So the rule is right and the wiring is not: e.g. the cloud list, `now`, the camera position or the subject check used in
the frame build differ from what the hook reports, or the hook reads a different PlayerView than the renderer.

## Evidence
`tests/e2e/m2c.spec.ts` "BUG-016 (fails until fixed) ..." (`test.fail`), notes in the run log of
`docs/qa/M2c-test-report.md` "Closing round"; screenshots `test-results/e2e/m2c-throwables-*`.

## Status: closed (not a bug: test harness), 2026-11-18
Root cause was the QA spec: the melee step held LMB for 500 ms per try, which swung the knife up to 3 times and killed B.
By the smoke check B was dead (B's own shot `test-results/shots/m2c-smoke-from-b.png` shows "Spectating QA Alpha"), and
a dead player is never smoke-hidden; the spectator's camera subject (A) is excluded by design (smoke.md). The game-developer
added unit tests in `src/game/ClientGame.m2c.test.ts` for the three cases with these numbers (alive: hidden both ways).
The spec now clicks once per swing, asserts exactly one hit and that B is alive before the smoke check, and logs `alive`
and `spectateTargetId`; the `test.fail` marker is removed (see the M2c report "Closing round").
